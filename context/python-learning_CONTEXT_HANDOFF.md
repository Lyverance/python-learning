## ЧАСТЬ 2 — Состояние разработки и границы

### 1. Исходная задача

Освоить Claude Code на практике — команды, работа с контекстом,
скиллы, настройка — чтобы применять в дальнейших задачах. Приоритет
сменён 2026-09-14: сначала владение инструментом, теория Python позже.

Добавилось 2026-09-15: привести в порядок раскладку файлов и
синхронизацию между телефоном, GitHub и облачными сессиями.

### 2. Definition of Done & Scope

**Фаза:** активная разработка.

**Готово, когда:**
- автор сам, без подсказки, начинает новую сессию и она знает контекст;
- автор сам заводит скилл под повторяющуюся процедуру;
- автор сам выбирает между `CLAUDE.md`, скиллом и хуком под задачу;
- каждый файл лежит ровно в одном месте, и автор знает, в каком.

**Вне объёма — сознательный отказ, не предлагать:**
- теория Python — отложена самим автором;
- перестройка `llm-prompts` — репозиторий рабочий, не учебный объект;
- установка Claude Code в Termux **через npm** — сборки под Android
  не существует, проверено;
- Agent Teams, `/batch`, параллельные агенты, множество MCP — нет
  задач такого размера;
- `/init` — затрёт написанный руками `CLAUDE.md`, который точнее
  генерируемого;
- второй учебный репозиторий — эта среда единственная;
- общая папка `repos/` — см. раздел 4, отброшено с порогом;
- перенос `ObsidianBase` — путь к нему зашит в `llm-prompts/bin/
  lpsync.sh:21` и в шорткат `~/.shortcuts/obsidian-sync`, плюс он
  прописан в настройках приложения Obsidian.

**Принятые компромиссы — достаточно, не улучшать:**
- спецификация сборки снимка скопирована внутрь скилла. Сослаться
  на файл там, где репозитория нет, не на что. Источник —
  `llm-prompts/handoff/HANDOFF_PROMPT.md`, копии производные;
- обмен с телефоном через `push`/`pull`;
- репозитории лежат в корне общей памяти рядом друг с другом —
  это уже одно правило, и оно выполняется.

### 3. Итоговые выводы и принятые решения

- **Пуш напрямую в `main` разрешён** автором. Отдельная ветка сессии
  не нужна.
- **`CLAUDE.md` пишется руками.** Критерий включения строки: меняет ли
  она будущее поведение сессии. План, обоснование и привязка
  к разговору — не меняют, вырезаны.
- **Личные скиллы `~/.claude/skills/` в облачных сессиях не
  работают** — подтверждено документацией. Доступны два уровня:
  проектный `.claude/skills/` и скилл на аккаунте claude.ai. Второй
  работает во всех репозиториях.
- **Скилл `handoff-snapshot` заведён и проверен.** Лежит в
  `llm-prompts/.claude/skills/handoff-snapshot/SKILL.md`, загружен
  на аккаунт claude.ai, синхронизирован в контейнер побайтово
  идентично. Синхронизация подтянулась без перезапуска сессии.
  Самодостаточен: проверяет наличие `bin/snapshot.sh`
  и `bin/handoff-diff.sh`, а не требует их.
- **`description` решает судьбу скилла.** Три части: что делает,
  когда применять реальными словами автора, когда не применять.
  Третья отсекает ложные срабатывания.
- **Критерий очистки контекста — не процент заполнения, а помехи:**
  сколько в контексте опровергнутых утверждений, которые продолжают
  влиять.
- **Абсолютные пути в скриптах не зашивать.** Скрипты `llm-prompts/
  bin/*.sh` вычисляют корень от своего расположения, путь к зеркалу
  вынесен в переменную `LPSYNC_MIRROR`. Именно поэтому переезд
  репозитория стоит четырёх правок документации, а не переписывания.
- **Зеркало Obsidian отставало от репозитория** (обнаружено
  2026-09-15). Копия `env/TERMUX_PROFILE.md` в зеркале была старше
  версии в git на два раздела и несла YAML-шапку, добавленную прямо
  в Obsidian. Источник — git, зеркало производное.

### 4. Отброшенные подходы

- **Третий репозиторий-полигон для скиллов** — скиллы не ломают код,
  полигон не нужен.
- **`/fewer-permission-prompts` как первое действие** — прогнан,
  результат пустой. В вебе контейнер новый каждую сессию, транскрипты
  не накапливаются. Плюс подтверждения в текущем режиме не
  запрашиваются.
- **Два скилла — проектный и глобальный** — заменены одним
  самодостаточным.
- **Вынос процедур из `CLAUDE.md` в скиллы ради экономии контекста** —
  мотив не подтвердился измерением, доля файла около процента.
- **Общая папка `repos/` для всех репозиториев — сейчас отброшена.**
  Из трёх переехать может только `python-learning`: `ObsidianBase`
  закреплён кодом и настройками приложения, `llm-prompts` переезжаемый,
  но правок требует, а выгода косметическая. Папка с одним
  репозиторием внутри и двумя снаружи — третье место, где надо помнить,
  что где. **Порог возврата к вопросу:** когда репозиториев станет
  столько, что нужный не находится с первого взгляда — практически
  пятый-шестой. Тогда переезжают все, кроме `ObsidianBase`, и
  клонированием заново, а не `mv`.
- **`mv` для переноса репозитория** — тащит права и метаданные,
  которые FUSE не переваривает. Заменено свежим клоном; старый каталог
  удаляется только после проверки нового.

### 5. Введённые термины и договорённости

- **Снимок (handoff)** — документ передачи контекста между сессиями.
  Спецификация — `llm-prompts/handoff/HANDOFF_PROMPT.md`.
- **Скилл** — папка с `SKILL.md`: YAML-шапка `name` + `description`,
  далее тело. В контексте всегда висит только `description`, тело
  читается при срабатывании.
- **Ворота** — `.githooks/commit-msg` в `llm-prompts`: правка файлов
  `core/`, `handoff/`, `audit/AUDIT_PROMPT.md` требует строки
  `FAILURES:` в сообщении коммита. Пути `.claude/skills/` и `env/`
  под ворота не попадают.
- **Зеркало** — копия части `llm-prompts` внутри Obsidian vault,
  собирается `bin/lpsync.sh` по списку `env/MIRROR.list`. Файл,
  изменённый прямо в Obsidian, перед затиранием откладывается
  в `$LP/.vault-conflicts/`.
- **Правила ответа** — четыре пронумерованных раздела в `CLAUDE.md`:
  основания, проверка, границы задачи, опасные изменения.

### 6. Открытые блокеры

- **Три копии спецификации снимка расходятся молча.**
  `handoff/HANDOFF_PROMPT.md` → вшитая копия в `SKILL.md` → загруженная
  копия на claude.ai. Правка первой не обновляет остальные, проверки
  расхождения нет.
- **Ворота `commit-msg` не действуют в клоне, подключённом к сессии
  чужого репозитория.** `.claude/hooks/session-start.sh` срабатывает
  при старте сессии по `llm-prompts`; сессия, подключившая репозиторий
  на ходу, приходит без `core.hooksPath`. Задавался вручную.
- **Скилл не проверен в репозитории без `bin/snapshot.sh`.** Ветка
  «таких скриптов нет» исполнена один раз — при сборке редакции
  2026-09-14 этого документа. Повторно не проверялась.
- **Два каталога `scripts`.** `~/scripts` содержит `big-five`
  и `vtt_clean.py`. В общей памяти есть отдельный
  `~/storage/shared/scripts`; его содержимое не смотрели. Одно имя,
  разное содержимое.
- **Результат запуска `lpsync` не проверен.** Команда выполнена
  автором 2026-09-15, вывод сессии не показан. Не известно, что
  отложилось в `$LP/.vault-conflicts/`.
- **`dotfiles` не синхронизирован.** Репозиторий
  `Lyverance/dotfiles`, последний push 2026-07-15. `.bashrc`
  с алиасами `lp`/`lps`/`lpsync`, `~/.ssh/config`, шорткаты
  `obsidian-sync` и `tg.sh`, обёртка `~/.llm-hooks/commit-msg`
  существуют в одном экземпляре на устройстве.
