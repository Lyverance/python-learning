## ЧАСТЬ 1 — Состояние

Читатель: **с доступом к проекту.**

Состояние не пересказывается — его печатают команды. Цифры в этом
документе считать устаревшими и перепроверить:

    cd ~/storage/shared/python-learning
    git log --oneline -5
    git status --short
    ls -a

Команды, печатающей состояние, у проекта нет — репозиторий учебный
и почти пустой. Ниже только то, что командой не проверяется.

**Расположение.** Рабочая копия — `~/storage/shared/python-learning`,
в общей памяти Android. Прежний клон `~/python-learning` внутри Termux
удалён 2026-09-15; двух копий больше нет. Причина переезда: приватный
каталог Termux недоступен файловому менеджеру Android и диалогу
загрузки файлов. Раздел FUSE требует `git config core.fileMode false`
и `git config --global --add safe.directory` — обе заданы.

**Репозиторий публичный** (`Lyverance/python-learning`). Профили
окружения, ключи, пути к приватной инфраструктуре сюда не кладутся
ни в каком виде.

**`proot` на этом устройстве заблокирован прошивкой.** Realme, как
и OnePlus и Oppo — бренды BBK — встроили средство, которое убивает
процессы под `proot`, определяя их по системным вызовам. Termux
предупреждает об этом официально; настройками и отключением phantom
process monitoring не лечится. Воспроизведено 2026-09-15 трижды:
убиты `apt-get update`, `dpkg-preconfigure`, `dpkg-deb --control`,
каждый раз с системным диалогом о «вредоносном приложении».
Пробросы файловой системы при этом работали, и проверка доступа
к репозиториям изнутри Ubuntu прошла успешно — упирается именно
подделка прав, которой `proot` добивается через `ptrace`.

**Долгие операции в Termux Android убивает отдельно от этого.**
Лечится `termux-wake-lock` перед запуском; после работы снимать
`termux-wake-unlock`, иначе держится и тратит батарею.

**Claude Code установлен на устройстве 2026-09-15**, версия 2.1.236.
Работает без `proot`. Устройство установки:

    $PREFIX/bin/claude        обёртка, 93 байта
    ~/.local/bin/claude-bin   бинарник, 331 929 832 байта

Обёртка состоит из одной содержательной строки:
`LD_PRELOAD= exec "$HOME/.local/bin/claude-bin" "$@"`.

Бинарник — официальный, `linux-arm64` с сайта Anthropic; sha256
сверена с `manifest.json` того же выпуска до правки. Затем ему
заменён ELF-интерпретатор командой `$PREFIX/glibc/bin/patchelf
--set-interpreter $PREFIX/glibc/lib/ld-linux-aarch64.so.1`. Правка
меняет в заголовке одну строку и увеличивает файл примерно на 131 КБ;
после неё sha256 закономерно отличается от опубликованной.

**Зачем обёртка.** Termux экспортирует всем процессам
`LD_PRELOAD=$PREFIX/lib/libtermux-exec-ld-preload.so`. Для
glibc-программы это ломает поиск библиотек, и она падает с
`…/glibc/lib/libc.so: invalid ELF header`. Сообщение сбивает с толку:
`libc.so` в glibc — текстовый ld-скрипт на 362 байта, настоящая
библиотека называется `libc.so.6`, и бинарник просит именно её.
Очистка переменной снимает подмену.

**Альтернатива обёртке — `grun`** из пакета `glibc-runner`. Проверена,
работает так же. Выбрана обёртка: делает одно понятное действие.

Установленные пакеты: `glibc-repo`, `glibc-runner` 2.0-3,
`patchelf-glibc` 0.19.1, `glibc` 2.44. Исполняемый файл `patchelf`
лежит не в общем `PATH`, а в `$PREFIX/glibc/bin/patchelf`.

Установка через npm невозможна — сборки под `linux-arm64-android`
не существует, проверено 2026-09-14.

**Следствие окружения.** Сессия работает со своим клоном в облаке.
Обмен файлами с телефоном — только через GitHub. Незакоммиченные
правки на телефоне сессия не видит.

**Второй репозиторий.** `Lyverance/llm-prompts` — рабочий проект
автора, приватный. Подключается инструментом `add_repo`, owner
`Lyverance`, repo `llm-prompts`, `access: push`. Загружать архивом
repomix не нужно: дороже и даёт устаревший срез.

**Правила работы с сессией** — в `CLAUDE.md` этого репозитория,
читается автоматически при старте. Здесь не дублируются.

## ЧАСТЬ 2 — Состояние разработки и границы

### 1. Исходная задача

Освоить Claude Code на практике — команды, работа с контекстом,
скиллы, настройка — чтобы применять в дальнейших задачах. Приоритет
сменён 2026-09-14: сначала владение инструментом, теория Python позже.

Добавилось 2026-09-15: привести в порядок раскладку файлов и
синхронизацию между телефоном, GitHub и облачными сессиями.

### 2. Definition of Done & Scope

**Фаза:** активная разработка.

**Готово, когда:**
- автор сам, без подсказки, начинает новую сессию и она знает контекст;
- автор сам заводит скилл под повторяющуюся процедуру;
- автор сам выбирает между `CLAUDE.md`, скиллом и хуком под задачу;
- каждый файл лежит ровно в одном месте, и автор знает, в каком.

**Вне объёма — сознательный отказ, не предлагать:**
- теория Python — отложена самим автором;
- перестройка `llm-prompts` — репозиторий рабочий, не учебный объект;
- установка Claude Code **через npm** — сборки под Android нет;
- установка Claude Code **через `proot-distro`** — прошивка убивает
  `proot`. Путь пройден до конца и закрыт; задача решена иначе,
  см. Часть 1. К `proot` не возвращаться;
- Agent Teams, `/batch`, параллельные агенты, множество MCP;
- `/init` — затрёт написанный руками `CLAUDE.md`;
- второй учебный репозиторий — эта среда единственная;
- общая папка `repos/` — см. раздел 4, отброшено с порогом;
- `Lyverance/dotfiles` — автор признал репозиторий ненужным
  2026-09-15: ранняя проба, её роль закрывает Obsidian;
- перенос `ObsidianBase` — путь к нему зашит в `llm-prompts/bin/
  lpsync.sh:21` и в шорткат `~/.shortcuts/obsidian-sync`, плюс он
  прописан в настройках приложения Obsidian.

**Принятые компромиссы — достаточно, не улучшать:**
- спецификация сборки снимка скопирована внутрь скилла
  `handoff-snapshot`. Сослаться на файл там, где репозитория нет,
  не на что. Источник — `llm-prompts/handoff/HANDOFF_PROMPT.md`;
- обмен с телефоном через `push`/`pull`;
- репозитории лежат в корне общей памяти рядом друг с другом.

### 3. Итоговые выводы и принятые решения

- **Пуш напрямую в `main` разрешён** автором. Отдельная ветка сессии
  не нужна.
- **`CLAUDE.md` пишется руками.** Критерий включения строки: меняет ли
  она будущее поведение сессии.
- **Личные скиллы `~/.claude/skills/` в облачных сессиях не
  работают.** Доступны два уровня: проектный `.claude/skills/` и скилл
  на аккаунте claude.ai. Второй работает во всех репозиториях.
- **Скилл `handoff-snapshot`** — в `llm-prompts/.claude/skills/`,
  загружен на аккаунт claude.ai, проверен побайтово. Самодостаточен:
  проверяет наличие `bin/snapshot.sh` и `bin/handoff-diff.sh`,
  а не требует их.
- **Скилл `distill`** — там же, коммиты `d126735` и `d71f22f`,
  загружен на аккаунт и проверен побайтово. Спецификацию не копирует,
  читает из `handoff/DISTILL_PROMPT.md`; в сессии без `add_repo`
  просит приложить её файлом и запрещает проход по памяти.
- **Способ проверить загрузку скилла:** смотреть `lastUpdated`
  в манифесте синхронизированных скиллов, а не только наличие
  каталога. Между загрузкой и синхронизацией контейнер показывает
  пустоту при загруженном скилле — вывод «не загружен» из этого
  ошибочен и был однажды сделан.
- **`description` решает судьбу скилла.** Три части: что делает,
  когда применять реальными словами автора, когда не применять.
- **Критерий очистки контекста — не процент заполнения, а помехи:**
  сколько в контексте опровергнутых утверждений.
- **Абсолютные пути в скриптах не зашивать.** Скрипты `llm-prompts/
  bin/*.sh` вычисляют корень от своего расположения, путь к зеркалу
  вынесен в `LPSYNC_MIRROR`.
- **Зеркало Obsidian отставало от репозитория.** Источник — git,
  зеркало производное. Прогнан `lpsync` 2026-09-15: 32 файла,
  одна правка отложена в `.vault-conflicts/process/`.
- **Claude Code ставится в Termux без `proot`.** Слой `glibc-runner`
  приносит glibc, `patchelf` подменяет в заголовке официального
  бинарника путь к загрузчику. `ptrace` не используется, поэтому
  защите прошивки убивать нечего.
- **Сумма сверяется до правки, не после.** `patchelf` меняет файл,
  и опубликованная Anthropic sha256 после этого перестаёт совпадать
  закономерно. Порядок: скачать, сверить, править.
- **Перед изменением файла — снять состояние, после — снять снова.**
  `--print-interpreter` до и после правки превратил непонятное
  `cannot execute: required file not found` в названный факт: внутри
  стоял путь `/lib/ld-linux-aarch64.so.1`, которого в Android нет.
  При неудаче видно, на каком из трёх шагов сломалось.
- **Исполняемые файлы не держать на разделе FUSE.** Бит исполнения
  там не сохраняется — то же свойство, из-за которого когда-то молча
  не срабатывали git-хуки. Бинарник перенесён в приватный каталог
  Termux копированием с последующей сверкой суммы, а не `mv`.
- **Долгие операции в Termux — под `termux-wake-lock`.** Без него
  Android убивает процесс; после работы снимать `termux-wake-unlock`.
- **Скорость сети на устройстве плавает** от 48 кБ/с до 2 МБ/с.
  Замеряется по строке `Fetched ... in ...` в выводе `apt`. Узким
  местом не является, но при медленном канале длинные операции
  надёжнее бить на короткие.

### 4. Отброшенные подходы

- **Третий репозиторий-полигон для скиллов** — скиллы не ломают код.
- **`/fewer-permission-prompts` как первое действие** — прогнан,
  результат пустой. В вебе транскрипты не накапливаются, выборки
  не будет никогда.
- **Два скилла — проектный и глобальный** — заменены одним
  самодостаточным.
- **Вынос процедур из `CLAUDE.md` в скиллы ради экономии контекста** —
  мотив не подтвердился измерением, доля файла около процента.
- **Общая папка `repos/`** — из трёх репозиториев переехать может
  только `python-learning`. **Порог возврата:** когда репозиториев
  станет столько, что нужный не находится с первого взгляда —
  практически пятый-шестой.
- **`mv` для переноса репозитория** — тащит права и метаданные,
  которые FUSE не переваривает. Заменено свежим клоном.
- **Linux через AVF, встроенный в Android 16 Terminal.** Отвергнут
  2026-09-15: VM изолирована, по умолчанию видит только Downloads.
  Репозитории пришлось бы клонировать внутрь — два клона каждого.
  В Android 16 QPR2 доступ расширен почти до всей общей памяти;
  есть ли QPR2 на устройстве — не проверяли.
- **`proot-distro` с Ubuntu.** Путь пройден до конца и закрыт
  2026-09-15. Ubuntu развернулась, пробросы файловой системы
  работали, репозитории изнутри были видны — но установка пакетов
  невозможна: прошивка убивает подпроцессы `dpkg`. Причина в Части 1.
  Rootfs удалён как бесполезный.
- **Готовые сторонние установщики Claude Code для Termux.** Вариант
  с «пропатченным нативным бинарником» не брать: посторонний
  исполняемый файл, через который пойдут учётные данные.
  `termux-linux-deployer` не брать: разворачивает code-server, роли
  агентов, MCP-серверы и три рантайма. Установщик
  `ferrumclaudepilgrim/claude-code-android` прочитан: берёт
  **официальный** бинарник Anthropic и сверяет контрольную сумму
  по манифесту Anthropic — это верно; но принудительно переключает
  DNS самого Claude Code на `8.8.8.8`/`8.8.4.4` через preload-скрипт
  `~/.local/share/claude/setdns.js`. Автору с VPS и Xray это
  не нужно — собирать вручную из официальных частей.

### 5. Введённые термины и договорённости

- **Снимок (handoff)** — документ передачи контекста между сессиями.
  Спецификация — `llm-prompts/handoff/HANDOFF_PROMPT.md`.
- **Скилл** — папка с `SKILL.md`: YAML-шапка `name` + `description`,
  далее тело. В контексте всегда висит только `description`, тело
  читается при срабатывании.
- **Ворота** — `.githooks/commit-msg` в `llm-prompts`: правка файлов
  `core/`, `handoff/`, `audit/AUDIT_PROMPT.md` требует строки
  `FAILURES:` в сообщении коммита. Пути `.claude/skills/` и `env/`
  под ворота не попадают.
- **Зеркало** — копия части `llm-prompts` внутри Obsidian vault,
  собирается `bin/lpsync.sh` по списку `env/MIRROR.list`. Файл,
  изменённый прямо в Obsidian, перед затиранием откладывается
  в `$LP/.vault-conflicts/`.
- **Правила ответа** — четыре пронумерованных раздела в `CLAUDE.md`:
  основания, проверка, границы задачи, опасные изменения.

### 6. Открытые блокеры

- **Три копии спецификации снимка расходятся молча.**
  `handoff/HANDOFF_PROMPT.md` → вшитая копия в `SKILL.md` → загруженная
  копия на claude.ai. Проверки расхождения нет.
- **Ворота `commit-msg` не действуют в клоне, подключённом к сессии
  чужого репозитория.** `.claude/hooks/session-start.sh` срабатывает
  при старте сессии по `llm-prompts`; сессия, подключившая репозиторий
  на ходу, приходит без `core.hooksPath`. Задавался вручную.
- **Скилл `handoff-snapshot` не проверен в репозитории без
  `bin/snapshot.sh`** повторно: ветка «таких скриптов нет» исполнена
  один раз, при сборке редакции 2026-09-14 этого документа.
- **Два каталога `scripts` с одинаковым содержимым.** И `~/scripts`,
  и `~/storage/shared/scripts` печатают `big-five` и `vtt_clean.py`.
  Какой рабочий и есть ли расхождения внутри — не смотрели.
- **Одна правка отложена в `.vault-conflicts/process/`.** Какой это
  файл и нужна ли правка — не смотрели. Реестры проекта живут
  в `process/`, проверить стоит.
- **Claude Code на устройстве проверен только на `--version`.**
  Реальная работа — вход в аккаунт, сеть, запуск подпроцессов, правка
  файлов, git — не проверялась. Если начнутся странности, первое, что
  пробовать: заменить в обёртке `LD_PRELOAD= exec` на `exec grun`.
- **Автообновление Claude Code с этой установкой не согласовано.**
  Штатная схема нативной установки (`~/.local/share/claude/versions/`
  плюс ссылка) не используется: бинарник положен руками и правлен
  `patchelf`. Новая версия, если скачается, придёт без правки
  и не запустится. Поведение не проверено. Отключается
  `DISABLE_AUTOUPDATER=1` в `env` файла `~/.claude/settings.json`;
  обновление тогда делается вручную — скачать, сверить, `patchelf`,
  заменить `claude-bin`.
- **Конфиги существуют в одном экземпляре на устройстве.** `.bashrc`
  с алиасами `lp`/`lps`/`lpsync`, `~/.ssh/config`, шорткаты
  `obsidian-sync` и `tg.sh`, обёртка `~/.llm-hooks/commit-msg`.
  Через `dotfiles` их не восстанавливать — репозиторий отброшен,
  см. раздел 2.

### 7. Следующий шаг

Запустить `claude` в `~/storage/shared/python-learning`, войти
в аккаунт и убедиться, что сессия читает файлы репозитория
и выполняет git-команды.

вывод версии. Репозиторий лежит на разделе FUSE, где `core.fileMode`
уже выставлен в `false`, — если git начнёт показывать изменения прав
у файлов, причина в этом, а не в Claude Code.
