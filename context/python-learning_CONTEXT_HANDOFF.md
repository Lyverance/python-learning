## ЧАСТЬ 1 — Состояние

Читатель: **с доступом к проекту.**

Состояние не пересказывается — его печатают команды. Цифры считать
устаревшими и перепроверить:

    cd ~/storage/shared/python-learning
    git log --oneline -5
    git status --short
    claude --version
    gh run list --repo Lyverance/llm-prompts --limit 5 \
      --json conclusion,displayTitle -q '.[] | .conclusion + "  " + .displayTitle'

Команды, печатающей состояние целиком, у проекта нет — репозиторий
учебный. Ниже только то, что командой не проверяется.

**Расположение.** `~/storage/shared/python-learning`, в общей памяти
Android. Прежний клон внутри Termux удалён 2026-09-15. Раздел FUSE
требует `core.fileMode false` и `safe.directory` — обе заданы.
Репозиторий **публичный**: профили окружения, ключи, пути к приватной
инфраструктуре сюда не кладутся.

**Claude Code на устройстве**, версия 2.1.272, работает без `proot`.
Обёртка `$PREFIX/bin/claude` разворачивает ссылку `~/.local/bin/claude`,
проверяет ELF-интерпретатор и подменяет его у новой версии — около
двадцати секунд с сообщением в stderr. Запасной экземпляр —
`~/.local/bin/claude-bin` (2.1.236). Автообновление включено.

**`proot` заблокирован прошивкой.** Realme, OnePlus и Oppo — бренды
BBK — убивают процессы под `proot`. Termux предупреждает официально,
настройками не лечится. Воспроизведено трижды.

**Remote Control.** Запускается `claude remote-control` из каталога
проекта под `termux-wake-lock`. Тогда выполнение остаётся в Termux,
а ввод идёт из приложения. Процесс должен жить: закроешь Termux —
сессия отвалится.

**Обмен сообщениями между сессиями односторонний.** Локальная видит
облачные через `/list-agents` и пишет им; облачная не видит никого
и ответить не может — полномочий на доставку не хватает. Первый шаг
всегда за локальной. Обратный путь — git.

**`gh` установлен и авторизован.** Локальная сессия проверяет CI сама.
Токен лежит открытым текстом в `~/.config/gh/hosts.yml`, область
`gist`, `read:org`, `repo`. На устройстве теперь два самостоятельных
доступа к GitHub — SSH-ключ и токен; при потере телефона отзывать оба.

**Auto memory машинно-локальна** и между машинами не переносится.
Поэтому снимок в git её не дублирует, а закрывает её дыру.

**Второй репозиторий.** `Lyverance/llm-prompts`, приватный.
Подключается `add_repo`, owner `Lyverance`, `access: push`. Клон
приходит обрезанным; для `bin/check.sh` и `bin/selftest.sh` нужна
история — `git fetch --depth=1000 origin main`, иначе `handoff-diff`
падает не по делу.

**Сабагенты.** `.claude/agents/doc-drift.md` — сверяет утверждения
документации с фактическим состоянием репозитория, только сообщает.
Агенты регистрируются при старте сессии: созданный на ходу по имени
не вызывается, живой перезагрузки у них нет, в отличие от скиллов.

**Аккаунтные скиллы в локальной сессии.** Затягиваются командой
`CLAUDE_CODE_SYNC_SKILLS=1 claude -p "перечисли доступные скиллы"` —
скачиваются в `~/.claude/skills/synced/` и дальше работают без
переменной. На 2026-09-15 не выполнено.

**Правила работы с сессией** — в `CLAUDE.md`, читается автоматически.

## ЧАСТЬ 2 — Состояние разработки и границы

### 1. Исходная задача

Освоить Claude Code на практике — команды, работа с контекстом,
скиллы, настройка — чтобы применять в дальнейших задачах. Приоритет
сменён 2026-09-14: сначала владение инструментом, теория Python позже.

Добавилось 2026-09-15: привести в порядок раскладку файлов и
синхронизацию между телефоном, GitHub и сессиями.

### 2. Definition of Done & Scope

**Фаза:** активная разработка.

**Готово, когда:**
- автор сам, без подсказки, начинает новую сессию и она знает контекст;
- автор сам заводит скилл под повторяющуюся процедуру;
- автор сам выбирает между `CLAUDE.md`, скиллом и хуком под задачу;
- каждый файл лежит ровно в одном месте, и автор знает, в каком.

**Вне объёма — сознательный отказ, не предлагать:**
- теория Python — отложена самим автором;
- перестройка `llm-prompts` — репозиторий рабочий, не учебный объект;
- установка Claude Code через npm — сборки под Android нет;
- установка через `proot-distro` — прошивка убивает `proot`, закрыто;
- GitHub MCP с персональным токеном — заменён на `gh`, см. раздел 4;
- Agent Teams, `/batch`, множество MCP — нет задач такого размера;
- второй учебный репозиторий — эта среда единственная;
- общая папка `repos/` — см. раздел 4, отброшено с порогом;
- `Lyverance/dotfiles` — признан ненужным, его роль закрывает Obsidian;
- перенос `ObsidianBase` — путь зашит в `lpsync.sh:21` и в шорткат.

**Принятые компромиссы — достаточно, не улучшать:**
- спецификация снимка скопирована внутрь скилла `handoff-snapshot`:
  сослаться на файл там, где репозитория нет, не на что;
- обмен с телефоном через `push`/`pull`;
- репозитории лежат в корне общей памяти рядом друг с другом.

### 3. Итоговые выводы и принятые решения

- **Пуш напрямую в `main` разрешён.** Отдельная ветка не нужна.
- **`CLAUDE.md` пишется руками.** Критерий включения строки: меняет ли
  она будущее поведение сессии. Целевой размер по документации —
  до 200 строк.
- **Личные скиллы `~/.claude/skills/` в облачных сессиях не работают.**
  Доступны проектный `.claude/skills/` и скилл на аккаунте claude.ai.
- **Скиллы `handoff-snapshot` и `distill`** — в
  `llm-prompts/.claude/skills/`, загружены на аккаунт, проверены
  побайтово. Первый несёт спецификацию внутри и работает везде; второй
  читает её из репозитория и в чате без `add_repo` просит приложить
  файлом.
- **Способ проверить загрузку скилла:** смотреть `lastUpdated`
  в манифесте синхронизированных скиллов, а не наличие каталога.
  Между загрузкой и синхронизацией контейнер показывает пустоту.
- **`description` решает судьбу скилла.** Что делает, когда применять
  реальными словами автора, когда не применять.
- **Разделение труда между сессиями.** Локальная: файлы, git, `gh`,
  запуск — всё, что на устройстве. Облачная: веб, документация, чужие
  репозитории, долгое без расхода батареи. Это разделение, а не
  симбиоз: Remote Control переносит ввод, а не возможности.
- **Критерий очистки контекста — не процент заполнения, а помехи:**
  сколько в контексте опровергнутых утверждений.
- **Абсолютные пути в скриптах не зашивать.** Скрипты `llm-prompts/
  bin/*.sh` вычисляют корень от своего расположения.
- **Тест, зашитый на имена, ломается при смене данных.** Три проверки
  зеркала в `selftest.sh` сверяли два имени, а назывались «зеркалит
  по списку». Исправлено `2aa5759`.
- **CI запускается на любой push, независимо от путей.** Ворота
  `commit-msg` смотрят на изменённые файлы, GitHub Actions — нет.
- **Документ устаревает раньше окружения.** `CLAUDE.md` утверждал, что
  автообновление ломает установку, когда обёртка уже чинила версии
  сама. Правится документ, а не реальность.
- **Зеркало Obsidian сужено до промтов** (`core/*.md`, `handoff/*.md`,
  `audit/*.md`). Реестры и служебные документы из него ушли: конфликт
  2026-09-15 случился в `process/FIXME.md`, которому там не место.
- **Харнесс не запускает `Agent` без разрешения.** Включают три
  источника: прямая просьба, `CLAUDE.md`, скилл. Разрешение и порог
  записаны в `CLAUDE.md`, раздел «Разведка»: ответ уместится
  в абзац, а чтения на десятки килобайт — это сабагент.
- **Сабагент возвращает только отчёт.** Прочитанное им в окно
  вызывающего не попадает. Замер 2026-09-15: агент сжёг
  82 228 токенов за 26 вызовов инструментов, в контекст пришёл
  один отчёт.
- **Отчёт сабагента — вывод модели, а не факт.** Числа и пути из него
  перед записью проверять командой.
- **Хук и агент не взаимозаменяемы.** Проверка выражается командой
  и должна быть обязательной — хук. Требует суждения — агент.
  Найденное агентом, если выражается командой, переезжает в ворота
  и больше не возвращается.
- **«Хук» означает два разных механизма.** Git-хуки запускает git
  по `core.hooksPath`; хуки Claude Code запускает сессия на событиях
  `SessionStart`, `PreToolUse`, `Stop` по `.claude/settings.json`.
- **Сабагент — не сессия.** Сабагент отчитывается в диалог, облачная
  сессия не отчитывается: доставка односторонняя, обратный путь —
  git или `claude --teleport`.
- **Про `/clear` в облачных сессиях данные расходятся.** Документация
  («Claude Code on the web», таблица управления контекстом) говорит
  «No, start a new session instead». Список команд в приложении
  2026-09-15 показывает `/clear` с описанием «Start a new session
  with empty context; previous session stays on disk». Что из двух
  верно — не проверено выполнением. Утверждать до проверки нечего.
- **Удаление сессии есть только в интерфейсе.** В наборе инструментов
  его нет, есть архивация и разархивация. В приложении на телефоне
  пункта удаления у архивной сессии нет (проверено автором
  2026-09-15); в браузере не проверялось. Архивация обратима и служит
  первым шагом к удалению.
- **Правка в зеркале — правка производной.** Галочка в чек-боксе
  ставится одним касанием: Obsidian рисует `- [ ]` кликабельным.
  Запретить на FUSE нечем, поэтому ставка на обнаружение, а не запрет.

### 4. Отброшенные подходы

- **Третий репозиторий-полигон для скиллов** — скиллы не ломают код.
- **`/fewer-permission-prompts` как первое действие** — прогнан,
  результат пустой: в вебе транскрипты не накапливаются.
- **Два скилла, проектный и глобальный** — заменены одним
  самодостаточным.
- **Вынос процедур из `CLAUDE.md` ради экономии контекста** — мотив
  не подтвердился измерением, доля файла около процента.
- **Общая папка `repos/`** — переехать может только один репозиторий
  из трёх. **Порог возврата:** когда нужный не находится с первого
  взгляда, практически пятый-шестой.
- **`mv` для переноса репозитория** — заменено свежим клоном.
- **Linux через AVF, встроенный в Android 16** — VM изолирована,
  по умолчанию видит только Downloads; репозитории пришлось бы
  дублировать внутрь.
- **`proot-distro` с Ubuntu** — пройден до конца и закрыт.
- **Сторонние установщики Claude Code** — вариант с пропатченным
  бинарником не брать: посторонний исполняемый файл на пути учётных
  данных. `termux-linux-deployer` не брать: разворачивает
  code-server, роли агентов, MCP-серверы и три рантайма.
- **Точные имена файлов в `env/MIRROR.list`** — заводят `lpsync`
  в непроверенную ветку, см. раздел 6. Только глобы.
- **Скилл как способ включить сабагентов** — скилл грузится
  по триггеру, а решение «читать самому или делегировать»
  принимается раньше. Место правила — `CLAUDE.md`.
- **Отдельный репозиторий под теорию** — поднято повторно
  2026-09-15, отклонено тем же правилом: учебная среда одна.
- **`--add-dir` для `llm-prompts` в сессию `python-learning`** —
  грузит скиллы, команды и агентов, но не `CLAUDE.md`, не
  `.claude/rules/` и не хуки. Машинерия без контракта. Под
  `llm-prompts` — отдельная сессия из его каталога.
- **GitHub MCP с персональным токеном** — заменён на `gh`: тот входит
  через код подтверждения и хранит токен сам. У MCP есть
  `--scope project`, который пишет заголовок с токеном в `.mcp.json`
  внутри репозитория; для публичного репозитория это утечка.

### 5. Введённые термины и договорённости

- **Снимок (handoff)** — документ передачи контекста между сессиями.
  Спецификация — `llm-prompts/handoff/HANDOFF_PROMPT.md`.
- **Скилл** — папка с `SKILL.md`: YAML-шапка `name` + `description`,
  далее тело. В контексте всегда висит только `description`.
- **Ворота** — `.githooks/commit-msg` в `llm-prompts`: правка файлов
  `core/`, `handoff/`, `audit/AUDIT_PROMPT.md` требует строки
  `FAILURES:`. Пути `.claude/skills/` и `env/` под ворота не попадают.
- **Зеркало** — копия части `llm-prompts` внутри Obsidian vault,
  собирается `bin/lpsync.sh` по списку `env/MIRROR.list`. Файл,
  изменённый прямо в Obsidian, перед затиранием откладывается
  в `$LP/.vault-conflicts/`.
- **Правила ответа** — четыре пронумерованных раздела в `CLAUDE.md`:
  основания, проверка, границы задачи, опасные изменения.
- **Сабагент** — вызов инструмента `Agent`: отдельное окно контекста,
  возвращает один отчёт и исчезает. Встроенные типы доступны без
  настройки; свои описываются файлом в `.claude/agents/`.
- **Расхождение (drift)** — утверждение в документации, которое
  опровергается читающей командой. Замысел и обоснование
  расхождением не считаются: их нечем проверить.

### 6. Открытые блокеры

- **Дефект `lpsync` на точных именах в `MIRROR.list`.** Правка,
  сделанная в зеркале, при уходе файла из репозитория не
  откладывается в `.vault-conflicts` — та потеря, против которой
  написан тест по находке внешнего аудита 2026-09-09. На глобах
  ветка работает. Воспроизведено вручную. Состав возвращён к глобам,
  путь не достигается, но код не исправлен. В реестр не записан:
  маршрутизация записей за автором. Лечение: починить `bin/lpsync.sh`
  и добавить в `selftest.sh` случай с точным именем; до починки этот
  случай сделает CI красным.
- **Ворота `commit-msg` не действуют в клоне, подключённом к сессии
  чужого репозитория.** `.claude/hooks/session-start.sh` срабатывает
  при старте сессии по `llm-prompts`; сессия, подключившая репозиторий

- **Самолечение обёртки проверено на одной версии.** `2.1.272`
  чинилась из состояния «лежит непатченной». Полный цикл —
  автообновитель скачал, обёртка починила — не наблюдался.
- **Два каталога `scripts` с одинаковым содержимым.** И `~/scripts`,
  и `~/storage/shared/scripts` печатают `big-five` и `vtt_clean.py`.
  Какой рабочий и есть ли расхождения внутри — не смотрели.
- **Три расхождения в `llm-prompts/env/`, найдены 2026-09-15,
  не исправлены.** Автор отложил правку. `TERMUX_PROFILE.md:166-168`
