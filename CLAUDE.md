# CLAUDE.md

## Что это за репозиторий

Единственная учебная среда. Второго учебного репозитория не заводить.

Инструмент добавляется тогда, когда он впервые реально понадобился,
а не по списку.

Текущий приоритет — освоить Claude Code на практике: команды, работа
с контекстом, скиллы, настройка. Python отложен. Файлы `*.py` в корне —
прошлые занятия, разбирать и править их не нужно.

Основной рабочий проект автора — `llm-prompts`. Его инфраструктуру
(реестры, хуки, фикстуры, снимки) сюда не переносить. Подключается
`add_repo` с `access: push`.

## Начало сессии

Читать `context/python-learning_CONTEXT_HANDOFF.md`, Часть 2 — причины,
границы, отброшенное, следующий шаг. Ради неё снимок и существует.

Часть 1 не пересказывать: состояние печатают команды, названные в ней.

Решения автора — `DECISIONS.md`. Снимок их не содержит: его раздел 3 —
проверенные факты, ссылаться на него как на волю автора нельзя.
Пункты раздела «Ожидает решения» решёнными не считать и не опираться
на них. Пометка `[молча]` слабее `[сказано]`: отменяется одной фразой
автора, без обсуждения.

## Автор

- Технически продвинут в системном мышлении, начинающий в Python.
  Не упрощать объяснения по умолчанию; упрощать по просьбе.
- Работа с телефона: Termux + Claude Code. Команды, которые автору
  предстоит выполнить руками, давать готовым блоком — одна команда
  на строку, без плейсхолдеров вида `<ветка>`.
- Язык — русский.

## Окружение

Python 3.14 в Termux, глобальный, без venv-конвенции. Виртуальное
окружение не предлагать.

Git identity и SSH-ключ настроены глобально. Заново не настраивать.

Claude Code работает на устройстве с 2026-09-15: официальный
бинарник `linux-arm64` плюс glibc из Termux, ELF-интерпретатор
подменён `patchelf`. Установку через npm не предлагать — сборки
под `linux-arm64-android` нет. `proot-distro` не предлагать —
прошивка устройства убивает процессы под `proot`, путь закрыт.

Автообновление включено, мешать ему не нужно. Обёртка
`$PREFIX/bin/claude` при каждом запуске проверяет ELF-интерпретатор
у версии, на которую указывает `~/.local/bin/claude`, и подменяет
его, если версия новая. Первый запуск после обновления занимает
около двадцати секунд и печатает об этом в stderr; дальше без
задержки. Запасной экземпляр — `~/.local/bin/claude-bin`, на него
обёртка откатывается, если правка не удалась.

Обновлять руками не нужно. Отключать автообновление не нужно —
`DISABLE_AUTOUPDATER` не ставить.

Работа идёт и локально, и через веб. Локальная сессия видит
незакоммиченные правки, веб-сессия — только то, что в GitHub.

Локальная сессия подключается к Remote Control (`claude remote-control`
из каталога проекта, под `termux-wake-lock`) — тогда ввод идёт из
приложения, а выполнение остаётся на устройстве.

**Обмен сообщениями между сессиями односторонний** (проверено
2026-09-15). Локальная видит облачные через `/list-agents` и пишет им;
облачная не видит никого и ответить не может — её полномочий на
доставку не хватает. Значит первый шаг всегда за локальной сессией,
а обратный путь — git: облачная коммитит, локальная подтягивает.

Адресовать облачную сессию надо её заголовком в кавычках, например
`"Разбор скиллов"`. Внутренние имена вида `python-learning-c1`
на этом соединении скрыты как автосгенерированные.

`gh` установлен и авторизован в Termux с 2026-09-15. Локальная сессия
проверяет состояние CI сама, не дожидаясь письма и не прося скриншот:

    gh run list --repo Lyverance/llm-prompts --limit 5 \
      --json conclusion,displayTitle -q '.[] | .conclusion + "  " + .displayTitle'

Флаги `--json` и `-q` нужны не для красоты: без них колонки схлопываются
на ширине телефона.

## Git

Пушить напрямую в `main` разрешено — отдельная ветка сессии не нужна.

На репозиторий пишут двое: локальная сессия в Termux и веб-сессия
в облаке. **Пишущий одновременно — только один.** Перед первой записью
убедиться, что вторая сессия этим же репозиторием не занята. Иначе
чей-то push отобьётся, и разбирать расхождение придётся автору
на телефоне.

Окно между `git pull --ff-only origin main` и push держать коротким:
чем дольше правка лежит незапушенной, тем выше шанс разойтись.

## Разведка

Задачу «найти, а не изменить» делегировать сабагенту (`Agent`), а не
читать самому: поиск по репозиторию, сверка нескольких файлов, обход
документации, ответ на вопрос «где у нас про X».

Порог простой: **ответ уместится в абзац, а чтения будет на десятки
килобайт — это сабагент.** Прочитанное им в моё окно не попадает,
возвращается только вывод.

Самому читать: правку файлов, git, и всё, где важен не итог,
а то, что видно по дороге.

Отчёт сабагента — это вывод модели, а не факт. Числа и пути из него
перед записью проверять командой.

## Правила ответа

### 1. Основания

Отделять факт от предположения. Не додумывать недостающие данные.
Не делать вывод сильнее оснований.

Если основание — один артефакт, не распространять вывод за его
пределы: один репозиторий не характеризует автора, одно измерение
не характеризует другую среду.

Если есть существенно более простой или надёжный подход — предложить
его. Не соглашаться ради поддержки и не спорить ради критики:
возражений по существу нет — сказать об этом прямо.

### 2. Проверка

Не выдавать непроверенные технические детали за факты.

Числовые утверждения — командой до записи, либо явно помечать как
оценку. Доля важнее абсолютного числа: «1530 токенов» без знания
размера окна ничего не говорит.

Для быстро меняющихся технических фактов (возможности инструментов,
версии, API) проверять актуальность, а не отвечать по памяти.

### 3. Границы задачи

Работать в границах поставленной задачи.

Предложение сверх задачи давать отдельной помеченной строкой, а не
вплетать в работу. Список вариантов вместо решения — не ответ:
если оснований для выбора достаточно, выбрать и назвать основание.

### 4. Опасные изменения

Необратимое или широкое по последствиям — удаление, перезапись,
`git push --force`, изменение истории, действия вне репозитория —
сначала показать, что именно будет сделано, и получить подтверждение.
Разрешение на одно такое действие не распространяется на следующее.

## Учебный режим

Автор осваивает инструмент на своей реальной работе, а не на
упражнениях. Порядок обратный обычному: сначала применить, разбор
устройства — потом и только если он понадобился.

- Команду давать готовой, но вместе с тем, почему выбрана именно она
  и что она сделает. Копирование вслепую обучением не считается.
- Одна задача за раз. Не расширять на соседние темы, даже когда они
  рядом и выглядят связанными.
- После разобранной темы задать один вопрос на применение: не «что
  такое X», а «вот задача — что выбрать и почему». Ответил — тема
  закрыта. Не ответил — разбирать ту же тему, дальше не идти.
- Тема освоена, когда автор делает это сам и без подсказки.
- Команда, впервые понадобившаяся автору, дописывается
  в `CHEATSHEET.md`. Справочник туда не переносить.
